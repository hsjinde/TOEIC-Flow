## 來源與流向

題目一律寫在 Obsidian vault，**不直接改 `content/*.json`**——那是產生物，下次 `build:content` 會覆蓋。

```
vault 文法/<分類>/<章節>.md        （題幹 + 選項）
vault 詳解/<分類>/<章節>.md        （答案 + 解析）
        ↓ pnpm build:content
content/grammar.json               （committed，bundle 進靜態站）
```

vault 位在 repo 之外（`D:\my-note\個人學習\多益`），所以 `git status` 不會顯示寫題的工作；repo 這邊唯一的產出物是重新生成的 `content/*.json`。

## 編號採 append-only

既有 q1–q5 一律不動，新題接在 q6–q15。

題目 id 由章節路徑與題號推導（`grammar/01_八大詞性與句型結構/01_名詞與代名詞#q5`），而這些 id 被持久化在 D1 的使用者 SRS 與錯題本記錄裡。重新編號會讓使用者資料無聲孤兒化，也會觸發 shrink-guard 的 id 汰換率檢查。Append-only 讓汰換率維持 0%，不需要 `--allow-shrink`；如果過程中想動用它，代表哪裡做錯了。

## 格式硬規則

以下限制來自 `parse-questions.ts` 與 `parse-answers.ts` 的實際行為。違反的題目會被 `merge.ts` 以 error 丟掉，`hasBlockingIssues()` 讓 build 失敗。

**題目檔**

- 新題**一律單空格**。多空格要求詳解的答案數與空格數完全相等，是最容易整批掉題的寫法。既有的 `01_名詞與代名詞` q5 是雙空格，不要模仿。
- 題幹寫在一行，選項寫在一行：`(A) w (B) x (C) y (D) z`。
- 選項行以外不可出現 `(A)`–`(D)` 形狀的括號——`extractOptions` 會把它吃掉當選項。
- 題幹內不可有以 `數字. ` 開頭的行，`PLAIN_QUESTION_RE` 會誤判成新題。
- 新題插在 `📖 詳解請見：[[…]]` 這行**之前**。
- 標題 `## 💪 練習題（5 題）` 改成 `（15 題）`。

**詳解檔**

- 每題一個 `## 題目 N：<標題>` 區塊，標題不可空白——那是 app 上顯示的題型名稱。
- 欄位順序：`**答案**`、`**詳細解析**`、`**相關文法點**`、`**相似題型提醒**`，區塊之間以 `---` 分隔。
- `**答案**: C` 只放一個字母。`extractAnswerKeys` 看到任何 `(1)` 形狀的文字就會走多空格分支，回傳錯誤的答案數。

## 查重

寫題之前先做工具。`scripts/check-duplicates.ts`，以 `pnpm check:duplicates` 執行，對**全庫所有題**（文法 + 閱讀 + 模擬考）做兩軸比對：

1. **正規化題幹相似度**——轉小寫、遮掉空格標記、收斂標點與空白後，比對 token 集合重疊率。
2. **正確答案目標詞碰撞**——取每題正解選項的文字，同一組（章節主題相近者）內重複即回報。

第二軸是真正的風險所在：針對同一個文法點寫 10 題時，最可能發生的不是抄同一個句子，而是換句話再考一次 `information` 或 `themselves`。

比對必須跨章。題庫裡本來就有主題重疊的章節對，只在章內查一定漏：

- `01/07_冠詞與數量詞` ↔ `01/08_數量詞與數詞用法`
- `01/05_介系詞` ↔ `01/14_介系詞片語作修飾語` ↔ `06/05_易混淆介系詞片語`
- `01/03_形容詞與副詞` ↔ `01/10_分詞形容詞與複合形容詞`
- `03/03_分詞與分詞構句` ↔ `03/09_獨立分詞構句`

腳本留在 repo 當常駐護欄，不納入 CI 硬規則。
